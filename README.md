# ILP circuits

Code for learning logical theories of neural computation from circuit
evidence. Circuits are discovered in transformer language models with
EAP-IG, described with Causal Functional Signatures (CFS), summarised as
Horn-clause architectural signatures learned by inductive logic programming
(ILP), and compared across tasks and models by signature distance,
theta-subsumption and live cross-model transfer.

The repository contains the code only. `data/` and `paper/` are empty
placeholders: prompt pools are generated by the scripts below, and all
experiment outputs are written under `analysis/` (not tracked).

## Layout

```
trace/
  circuits/            path-patching utilities used by the attribution code
  mechint/
    core/              EAP-IG attribution, circuit graphs, evaluation, validation statistics
    cfs/               Causal Functional Signatures: DLA scores, attention role profiles
    storage/
      ilp/             ILP architectural signatures, signature distance, subsumption
      owl_exporter.py  TTL/OWL export of circuits (four-layer ontology)
      results_export.py  per-task results JSON (layers 0-3)
    ontology/          RDF schema for the circuit knowledge graph
    query/             SPARQL interface and pattern analysis over stored circuits
    transfer/          transfer engine: signature retrieval + behavioural/causal validation
    baselines.py       random-circuit baselines
    baselines_structural.py  WL kernel, attributed WL, feature-vector and RF/stump baselines
    heldout.py         leave-one-split / leave-one-variant-out evaluation
    pipeline.py        reconstruct_graph, CFS and ILP_arch pipelines, distance reports
```

Top-level scripts are the experiment drivers; shell wrappers chain them.

## Installation

```bash
conda env create -f environment.yml
conda activate ilp_circuits
pip install -e .
python -m spacy download en_core_web_sm   # attention role labelling

```

## Pipeline

Model short names follow the HF id with the organisation and punctuation
removed, e.g. `EleutherAI/pythia-1b -> pythia1b`, `Qwen/Qwen2.5-7B -> Qwen2.57B`.

### 1. Prompt pools

| Script | Purpose |
|---|---|
| `generate_prompt_variants.py` | Generate three syntactic variants (v1-v3) of every task (ten semantic roles, IOI, Greater-Than) into `data/variants/`. CPU, deterministic. |
| `generate_extra_tasks.py` | Extra tasks (SVA, Colored Objects) into a separate pool root `data/variants_extra/`. |
| `pool_id.py` | Content fingerprint of a pool. Stored in each model's `coverage.json` so a filter built from a different pool can never be reused. |
| `filter_variants.py --model <hf-id>` | Per-model single-token and both-correct filtering, writes `data/variants_filtered/<model>/` and the coverage gate. |
| `split_variants.py --model <short>` | k disjoint splits per (task, variant) into `analysis/<short>/splits_variants/`. |
| `split_datasets.py`, `filter_greater_than.py` | The earlier single-pool equivalents used for the first 5-task and 12-task runs. |

### 2. Circuit discovery (GPU)

| Script | Purpose |
|---|---|
| `run_experiment.py` | Five-task pipeline on one model: EAP-IG discovery, TTL/JSON export, CFS, ILP_arch, layer figures, transfer engine. Edit `BASE_MODEL` at the top. |
| `run_experiment_multi.py --model <hf-id> --variants v1 v2 v3` | Twelve tasks x variants x splits. Records a k-sweep of faithfulness per edge budget inside each results JSON. |
| `run_cfs_scaled.py` | CFS (layer 2) for every k* circuit of the twelve-model evaluation. |
| `recompute_cfs_profiles.py` | Recompute linguistic and task-specific attention profiles in place. |
| `test_ksweep_equivalence.py` | Certifies the two k-sweep guarantees (sequential stability, budget equivalence) on the current backend. |

Wrappers: `run_variants_server.sh` (one model set, steps 1-2 plus held-out),
`run_variants_small.sh` / `run_variants_large.sh` / `run_variants_gpu0.sh` /
`run_variants_gpu1.sh` (model sets by memory class), `run_variants_extra.sh`
(extra tasks), `run_large_server.sh` (7B class), `run_all.sh` (original
three-model pipeline).

### 3. Post-processing (CPU, stored results only)

| Script | Purpose |
|---|---|
| `select_kstar.py --model <short> --tau 0.5` | Faithfulness-matched edge budget k* per model and the k*-trimmed pool `analysis/<short>-k<K>_multi/`. |
| `run_heldout.py --model <short> --by variant` | Leave-one-out pooled ILP evaluation. |
| `run_baselines.py` | WL kernel, attributed WL, feature-vector distance, random forest and decision stump against ILP signature distance. |
| `run_random_baselines.py`, `run_random_baseline_scaled.py` | Size-matched random subgraphs; permutation significance of the real circuits. |
| `run_transfer_matrix.py --models ... --by variant` | Static cross-model signature retrieval over every ordered model pair. |
| `run_live_transfer.py`, `run_live_transfer_scaled.py` | Live transfer: retrieve a candidate on the target model and validate it behaviourally and causally (GPU). |
| `run_subsumption_all12.py`, `run_dt_by_task_all12.py` | Theta-subsumption analysis and per-task causal contribution over all k* pools. |
| `threshold_sensitivity.py` | Sweep of every validation threshold from stored evaluation records. |
| `generate_clause_tables.py` | Learned-clause tables (clause body, confidence, LOO-F1, complexity) from the results JSONs. |
| `statistical_tests_v2.py`, `sig_tests.py`, `rq1_cfs_significance_tests.py`, `dsyn_weight_sensitivity.py` | Significance tests and sensitivity checks on the stored results. |
| `probe_distance_seed.py` | Checks that the current hash seed reproduces the archived distance matrices (clause ties resolve by generation order; run with `PYTHONHASHSEED=0`). |

`run_postprocess.sh` chains k* selection, held-out evaluation and the transfer
matrix. `run_missing_experiments.sh` runs the eval-only phases (live transfer,
random baseline, extra task) split over two GPUs.

### 4. Figures

`generate_figures.py` (distance heatmaps, baseline comparison),
`plot_crossfamily_figures.py` (faithfulness vs budget, held-out separation,
transfer), `plot_cfs_figures.py` (DLA and attention-profile figures),
`plot_distance_matrices_all12.py` / `plot_distance_matrices_scaled.py`
(per-model signature distance matrices), `plot_layer1_circuits.py`,
`plot_layer3_architectural.py` and `visualise_layers.py` (per-layer figures
used by `run_experiment.py`). `plot_style.py` holds the shared palette.

## Results layout

```
analysis/<short>/splits_variants/          per-(task, variant) split CSVs
analysis/<short>_multi/results/            one results JSON per (task, variant, split)
analysis/<short>_multi/circuits/           TTL exports of the same circuits
analysis/<short>_multi/heldout/            leave-one-out reports
analysis/<short>-k<K>_multi/results/       k*-trimmed pool
analysis/<short>_multi/results/distance_report.json   ILP signature distances
analysis/transfer/                         transfer matrix and live transfer records
analysis/baselines/                        random-circuit baselines
analysis/tables/                           aggregated tables
```

Each results JSON has four layers: provenance (layer 0), structure (layer 1),
CFS (layer 2) and the learned architectural signature (layer 3).
